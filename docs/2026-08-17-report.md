## 4. 에이전트 체제

| 에이전트 | 역할 | 등급 |
|---|---|---|
| 정찰 | 이길 판을 고른다 | L2 |
| 취재 | 재료 빈 곳을 채운다 | L2 |
| 작가 | 글을 쓴다(Solar) | L1 |
| 편집 | 검사·판정 | L2 |
| 관측 | 순위를 잰다 | L0 |
| **학습** | **관측 → 파라미터** | **L2** |
| 면역 | 사고 봉쇄 | L1 |
| 관제 | 조율·보고 | L1 |
| **사령관** | **코드 수정안 작성** | L3-제한 |

**L3(코드 자동 수정)은 영구 금지**입니다. 사령관은 수정안을 만들고 **승인을 기다립니다.**
손댈 수 없는 곳: 헌법·게이트·`tests/`·자기 안전장치.
특히 `tests/`를 막은 게 핵심입니다 — 테스트를 고칠 수 있으면 자기 검증을 무력화합니다.

**보시는 곳**: `ollinda.kr/admin/agents` · `ollinda.kr/admin/commander?scan=1`

생성이 `done`으로 찍히는데 산출물이 0건인 일이 **세 번** 있었습니다. 원인이 둘로 갈립니다.

1. **크레딧 전면 차단**(위 11번) — 고쳤습니다.
2. **제 배포가 진행 중 생성을 죽였습니다.** 헌법 5장이 경고한 그것입니다.
   `safe-push.sh`가 두 번은 막아줬지만(fail-closed 정상 작동), 배포 직후 트리거한
   생성은 다음 배포에 죽었습니다.

**교훈**: 생성을 돌려놓고 배포하면 안 됩니다. 저는 밤새 이 순서를 여러 번 어겼습니다.
`safe-push.sh`가 없었으면 더 많이 죽였을 것입니다.

또 하나 — **죽은 생성이 `done`으로 남습니다.** 실제로는 아무것도 안 만들었는데
완료로 표시됩니다. 이건 아직 안 고쳤습니다(별건).

> **"만들었다"와 "그 경로로 간다"는 다르다.**

| 만든 것 | 실제로는 |

그래서 골든에 **연결 검사**를 넣었습니다 — 소스에서 실제 호출 지점을 확인합니다.

### 제가 박은 골든이 틀렸던 것도 하나

아침에 "짧은 보조 호출은 라우팅을 타지 않는다"를 박았습니다.
이유는 "추론 모델은 느리다"였고 속도 걱정 자체는 맞았습니다.
그런데 그게 **크레딧 0에서 세트를 통째로 죽이는 원인**이 됐습니다.
속도는 라우팅을 막는 대신 추론 강도를 낮춰서(`aux → low`) 풀어야 했습니다.

골든을 뒤집고 **왜 틀렸는지**를 그 자리에 적었습니다.

## 9. 제가 밤새 낸 판단 착오 하나 — 시간 기준

"생성이 됐는데 글이 없다"고 **세 번** 보고했습니다. 그중 마지막은 제 착오였습니다.
DB는 **UTC**로 기록하는데 저는 **KST 기준**으로 조회했습니다.
`created_at > '2026-08-17T12:00'` 같은 조건이 9시간 뒤를 가리켜 아무것도 안 잡혔습니다.

실제로는 그 시각에 이미 세 건이 나와 있었습니다.

| 글 | 시각(UTC) | 원가 | 경로 |
|---|---|---|---|
| fc316bc5 | 10:30 | $0.0147 | upstage |
| 4e347089 | 10:13 | $0.0110 | upstage |
| 017732ac | 09:53 | $0.0119 | upstage |

**다만 그 오판을 쫓다가 진짜 결함 둘을 찾은 것도 사실입니다** — 크레딧 전면차단과
보조 호출 Anthropic 직행. 둘 다 실재했고 고쳤습니다.

교훈: 시간 조건으로 "없다"를 판정할 때는 타임존을 먼저 확인해야 합니다.
`없다`는 결론은 조회가 맞았을 때만 유효합니다.
