# 통합검색 노출 전략 — 상세

CLAUDE.md의 헌법 조항을 실행하는 방법. 노출 관련 작업 착수 전 이 문서를 읽고,
[[research-protocol]]에 따라 최신 상태를 조사한 뒤 설계한다.

## 지면 4개 — 업종마다 승부처가 다르다

통합검색은 한 판이 아니라 네 판이다.

| 지면 | 무엇이 순위를 정하나 | 코드가 할 수 있는 것 |
|---|---|---|
| 플레이스(지도) | 등록정보 완성도·사진·새소식·리뷰 | 상세설명 초안, 새소식 초안, 순위 추적 |
| 블로그·통합탭 | 글 구조·실경험·발행 리듬 | 생성 전 과정 |
| AI 브리핑 | 추출 가능성(질문형 소제목·표·FAQ·수치) | 구조 게이트 |
| 웹문서 | 자체 도메인 페이지·구조화 데이터 | 미구현 |

**전 지면 동일 투자 금지.** tenant마다 실측으로 승부 지면을 확정하고 화력을 모은다.
방문 서비스는 플레이스가, 매물형은 콘텐츠 지면이 강한 경향이 있으나 **판정은 실측으로만**
한다(`app/services/exposure.py`, `blogreach.blocks_for`).

### 지면이 없는 판은 글로 못 뚫는다
실측(2026-08-01~02): '부산 썬팅' 첫 화면은 플레이스·클립·숏텐츠·쇼핑뿐 — 블로그 자리가
아예 없다. 여기 겨냥한 글은 아무리 잘 써도 노출되지 않는다. 반면 '부산 동구 썬팅'은
인기글 블록이 있고 실제로 노출됐다. **키워드 선정이 글 품질보다 먼저다.**

## 네이버가 노출시키는 방식 — 실측 (2026-08-16)

기계는 둘이다. **수집(크롤)과 노출(랭킹)은 다른 기계다** — 섞어 보면 오판한다.

### 노출 기계: 네이버는 글이 아니라 **문단**을 노출시킨다

실측 방법: 3업종(썬팅·중고차·이어폰) 12개 검색어로 상위 글 339개를 조회해,
**여러 검색어에 걸친 같은 글의 요약문(description)이 검색어마다 달라지는지** 대조.

결과 — 썬팅 83%(5/6) · 중고차 100%(1/1) · 이어폰 83%(10/12). **평균 84%가 바뀐다.**

```
KNBOX 엑센트 글 (동일 URL)
  '부산 썬팅'  9위 → 도입부 문단
  '썬팅 가격' 10위 → "중저가 30만원대 / 중고가 50만원대 / 프리미엄 80만원대"
```
가격을 물으면 **가격 문단을 찾아 뽑아온다.** 도입부를 자르는 게 아니다.

**따라오는 사실 둘:**
1. **같은 글이 검색어마다 전혀 다른 대접을 받는다** — 한 글이 `부산 썬팅 1위` ↔ `차량 썬팅 28위`.
   "좋은 글을 쓰면 여러 검색어에서 뜬다"는 **틀렸다.**
2. **검색어마다 판이 분리돼 있다** — 두 검색어 이상에 걸친 글 비율: 중고차 0.8% · 썬팅 4.2% ·
   이어폰 15.8%. **지역이 붙을수록 판이 갈라진다.** 한 글로 여러 지역 키워드를 먹는 일은
   실측상 일어나지 않는다 → 헌법의 "세트 = 한 소재 = 한 키워드"가 남의 글 339개로 증명됐다.

### 그래서 글은 이렇게 쓴다

- **노리는 질의마다 그 질의에 정면으로 답하는 독립 문단**이 글 안에 서 있어야 한다.
  가격을 노리면 가격 숫자·구간이 **한 문단에 모여** 있어야 한다. 흩어놓으면 뽑아갈 덩어리가 없다.
- **도입부 집중은 위험하다.** 도입부가 항상 뽑히지 않는다.
- **문단을 '답변 단위'로 설계한다** — 각 문단이 하나의 질문에 대한 답처럼 읽혀야 한다.

### 순위가 움직이는 방식 (자사 `blog_search` 궤적 6개 — 표본 얇음)

```
19위 진입 → 3일 뒤 1위 안착         (부산 기장 중고차판매)
미노출   → 3일 뒤 1위               (부산 기장군 중고차판매)
17위 진입 → 2주에 걸쳐 21위로 밀림   (부산 기장에서 전국으로)
1위 3주 유지 → 08-07 통째로 사라짐   (2026 팰리세이드 썬팅)
색인됐으나 4주간 한 번도 진입 못 함   (2026 기아 쏘렌토)
```
- **진입 순위는 최종 순위가 아니다. 재평가가 3~5일 안에 일어난다.**
  발행 직후 순위로 성패를 판단하면 오판이다.
- **1위는 영구 계약이 아니다.** 계속 다시 겨룬다.
- **색인 ≠ 노출.** 색인되고도 한 번도 안 뜨는 글이 있다.

### 수집 기계: Yeti (자체 도메인 로그 408건 중 Yeti 17건 전수)

| 확인된 것 | 근거 |
|---|---|
| 몸이 둘 — 텍스트 수집기 / 렌더 수집기 | UA 2종. 렌더 쪽은 `Chrome/149`로 CSS·이미지까지 실제로 그린다 |
| 이미지는 20초에 1장 | 간격 11·20·19·20·21·20초 — 랜덤 아님. 사진 22장이면 이미지에만 7분 |
| 매 세션 사이트맵부터 | 4세션 중 3세션이 `/sitemap.xml` 최우선 |
| **추측하지 않는다** | 404 **0건**(Googlebot·bingbot도 0%). AI봇은 72~99% |
| 요청마다 IP가 다르다 | 17요청 17IP, 4개 대역 → IP 단건이 아니라 **공식 대역 전체**로 판별해야 한다 |
| 재방문 2일 주기 | 8/10 → 8/12 → 8/14 |

→ **알려주지 않은 페이지에는 오지 않는다.** 사이트맵과 링크가 진입로의 전부다.

**자체 도메인 조치(2026-08-17)** — 외부 SEO 진단이 "색인할 내용이 없다"고 지적했고 사실이었다.
- 그전: 사이트맵 5개(`/`·`/intro`·`/privacy`·`/terms`·`/refund`), 실질 콘텐츠는 홈 하나뿐.
  `lastmod`는 5개 전부 `landing.py` 파일 mtime — 랜딩을 매일 고치니 **약관까지 매일
  "오늘 바뀜"**으로 신고됐다. 전부 바뀌었다는 사이트맵은 아무것도 안 바뀐 것과 같다.
- 조치: `app/guides.py` 실측 기록 6편 + `/guide` 목록 → 사이트맵 12개.
  `lastmod`는 **페이지마다 자기 날짜**(가이드는 글의 `updated`, 법적 문서는 개정일 상수).
- 원칙: 내용은 **직접 잰 것만**. 얇은 글을 수십 개 찍는 것은 우리가 고객에게 금지하는 짓이다.
- 골든: `tests/test_guides.py`(사이트맵 편입·lastmod 뭉개짐·제목/canonical 중복·본문 두께).

### 상위 글 해부 — 실측 (kw_anatomy, 검색어 29개 / 글 125개, 2026-07-27~08-16)

| 지표 | 중간값 | 범위 |
|---|---|---|
| 글자수 | **1,757자** | 1,119 ~ 2,326 |
| 사진 | **21장** | 3 ~ 52 |
| **소제목** | **2개** | 0 ~ 5 |
| 표 있는 글 | **0%** | 0 ~ 100 |
| 영상 있는 글 | 20% | 0 ~ 60 |
| 상위 글 나이 | 85일 | **7일 ~ 3,599일** |

- **소제목 2개** — "잘게 많이 나눠라"는 통념과 반대다. 문단 단위 노출 실측과 합치면
  **잘게 쪼갤수록 뽑아갈 덩어리가 사라진다.** 적게 나누고 두껍게가 실측에 맞다.
- **판의 나이가 검색어마다 10년 차이다** — '썬팅 계급도 가격' 7일 / '부산 신차썬팅' 16일 vs
  '부산 중고차판매' 3,599일 / '부산 중고차' 3,463일. 뒤쪽 판은 새 글로 못 뚫는다.
  **키워드 선정이 글 품질보다 먼저**라는 근거가 하나 더 늘었다.
- 한계: 검색어당 상위 4~5개, 업종이 썬팅·중고차에 치우쳐 있다.

### 확정과 추정을 가른다

- **확정**: 위 실측 전부(자체 서버 로그 + 공개 검색 API 조회).
- **추정**: C-Rank·D.I.A.+·스마트블록이라는 **이름**은 업계 해설이지 네이버 공식 문서가 아니다.
  관측된 궤적이 그 설명과 맞아떨어질 뿐 우리 데이터로 확정한 것이 아니다.
- **관측 불가**: 남의 블로그에 온 Yeti 로그는 네이버 서버에 있어 영원히 못 본다.
  봇의 *행동*이 아니라 봇의 *판정 결과물*(요약문·순위·색인)만 역추적할 수 있다.

## 노출을 만드는 순서

**1. 롱테일 → 상향 등반.** 큰 키워드 직행 금지. 검색량 관문을 통과한 지역·속성 롱테일
에서 1페이지를 확보하고 점차 올라간다.

**2. 발행 일관성.** 주 2~3회 리듬이 지수다. 매물이 없으면 정보형(트랙 B)으로 리듬을
유지한다. 리듬 붕괴는 노출 붕괴다.

**3. E-E-A-T 실경험.** 네이버는 무색무취한 AI 글을 누락시킨다. 실경험(사장 Q&A)·실값·
실서류·정직 고지가 입장권이다. **정직 게이트는 윤리이자 SEO 전략이다.**

**4. 구조화 = 추출 가능성.** 질문형 소제목·표·FAQ·수치가 AI 브리핑 인용 조건이다.
소제목 없이 긴 단락만 이어지면 AI가 정보를 못 뽑아 브리핑에 안 쓰인다.
**이는 브리핑만의 조건이 아니다** — 블로그 순위도 문단 단위로 뽑힌다(위 「노출시키는 방식」).
질의별 독립 답변 문단이 구조화의 목적이다.

**5. 지면 상호 신호.** 블로그↔공개페이지↔플레이스 새소식↔SNS가 서로 밀어준다.
세트 1건 = 다지면 동시 생산.

## 키워드 — 손님이 치는 말로

**업종명은 공급자 용어다.** 사업자등록증식 업종명을 그대로 쓰면 안 된다.
`seo.searcher_term()`이 공급자 접미어를 뗀 변형을 만들어 **실측 검색량·기회지수로 승부**를
붙인다(정답을 코드에 박지 않는다).

실측 예: `중고차판매`(6,580회, 기회 0.0027) vs `중고차`(271,600회, 기회 0.0509) → 중고차 승.
`자동차정비`는 유지된다 — `자동차`가 검색량 18배지만 문서 2,642만 건이라 기회에서 진다.

**거래 방향이 반대인 검색어는 제외한다.** 파는 가게에 '중고차팔기'(자기 차를 처분하려는
사람)는 손님이 아니다. `seo.keyword_intent_ok()`가 LLM 1콜 + 7일 캐시로 판정한다.

**기회지수 = 검색량 ÷ 문서수.** 검색량만 큰 포화 키워드보다 기회지수가 높은 판을 고른다.

## 측정

**지면 지도**: 맥 로컬 Playwright가 통합검색 첫 화면 블록 구성을 읽어
`/admin/blocks-ingest`로 보낸다(`insight/blocks.py`, `nightly.py` — 매일 새벽 4시).

**지면 인정 기준**: 블로그 글이 **2개 이상 나열된 블록**만 블로그 지면이다. 플레이스에
딸린 업체 블로그 링크 1개는 지면이 아니다.

**알려진 계측 결함 (2026-08-16 발견, 미수정)** — 고치기 전까지 아래 값으로 판단하지 않는다.
- `rank_snapshots.kind='blog'`는 실제로 `place.rank()`(지역검색) 결과다(`ranktrack.py:64`).
  `kind='place'` 행과 값이 100% 동일한 중복이며, **진짜 블로그 순위는 `blog_search`뿐이다.**
- `blog_publishes.indexed_at`은 네이버 색인 시각이 아니라 **우리가 확인한 시각**이다.
  7/14 06:39~06:40에 3건, 7/24 22:31에 2건이 동시 색인으로 찍힌 것이 증거(배치 확인의 흔적).
  "색인 981시간" 류 숫자는 읽으면 안 된다. 발행 직후 확인분(0.1~0.3시간)만 색인 상한으로 유효.
- `place.rank()`의 반환 `0`은 순위가 아니라 **상위 5위 밖(미노출)** 이다(`place.py:245`).

**자사 판정**: 자사 블로그 ID·플레이스 ID·업체명 정확 일치만. 블록 존재나 키워드 일치는
노출이 아니다. **블록 귀속은 미검증이므로 화면에 블록명을 쓰지 않는다**(→ [[lessons]]).

**추적 키워드**: 수동 등록 금지. 발행 글 canonical + 생성물 타깃 키워드에서 자동 도출
(`ranktrack.tenant_keywords`). 표기는 구어형으로 통일하되 표시·추적 층에서만 바꾼다.

## 절대 금지

키워드 스터핑 · 내용 복제 변주 · 트래픽/리뷰 조작 · 검색량 없는 키워드 욱여넣기 ·
날조로 게이트 통과. 단기 순위를 위해 하나라도 하는 순간 tenant 블로그 전체가 죽는다.
어떤 기능 요청이 와도 거부한다.

리워드 트래픽(돈을 주고 검색·클릭을 시켜 순위를 올리는 것)은 위 금지에 해당한다.
실제 손님에게 보상을 주는 판촉(방문·리뷰 기반)은 다른 것이며 허용된다.
