# 사건 계보 — 원인과 교훈

실제로 터진 것만 적는다. 각 항목은 코드 주석·실측 기록에 근거가 남아 있다.
새 사건은 맨 아래에 덧붙이고, 고친 코드에 같은 날짜를 주석으로 남긴다.

---

## 생성 품질

### 2026-07-27 · 캐스퍼/토레스 — 세트 간 소재 오염
토레스 세트 캡션이 "오늘 들여온 캐스퍼"를 서술했다. 원인은 채널마다 타깃 키워드를
재결정하면서 큐가 회전해, 캡션이 다른 차종 키워드를 받은 것.
**교훈**: 세트 = 한 소재 = 한 키워드. 키워드는 세트당 1회만 결정하고 전 채널이 공유한다.
→ `app/services/generate.py` `generate_for` 상단 `asset.target_kw` 승계

### 2026-07-28 · 풀네임 반복 — 공식 지명이 글을 지배
'부산광역시 동구 썬팅업체'가 타깃이 되자 모든 글이 풀네임을 반복했다.
**교훈**: 행정구역 풀네임은 검색량이 0에 가깝다. 표면에 쓰는 지역 토큰은 canonical
하나로 통일한다. → `app/seo.py` `canonical_region`, `_kw_shorten`

### 2026-08-01 · 마커 날조 — 보정이 [사진N]을 수십 개 만들어냄
재작성 프롬프트가 마커 개수를 명시하지 않아, 보정본이 없는 사진 마커를 창작했고
안전 게이트가 보정 전체를 폐기했다(점수 정체의 진짜 원인).
**교훈**: 재작성 지시에는 불변량(마커 개수·구조)을 숫자로 못 박는다.

### 2026-08-01 · 업종명 오용 — 사업자등록증 용어로 검색어를 잡음
'중고차판매' 6,580회 vs '중고차' 271,600회(41배). 확장 키워드에 '중고차팔기'(자기 차를
팔려는 사람 = 정반대 손님)까지 섞였다.
**교훈**: 업종명은 공급자 용어다. 손님이 치는 말로 바꾸고(`seo.searcher_term`),
거래 방향이 반대인 검색어는 제외한다. → [[exposure-strategy]]

### 2026-08-01 · 화자 뒤집힘 — 파는 사람의 도구가 사는 사람의 글을 냄
'중고차판매 가격 걱정?'을 고치려다 "손님 관점으로 써라"로 과교정해, 가게가 자기 매물을
소개하는 글이 구매자 사용기("중고차 후기 … 직접 검수기")처럼 나왔다.
**교훈**: 화자는 가게(파는 쪽), 청자는 손님(사는 쪽). 손님 말은 손님의 고민을 부를 때만.

## 파이프라인 · 동시성

### 2026-07-31 · 배포가 진행 중 스레드를 죽임
재배포 재시작이 다시쓰기 스레드를 죽여 'running'이 영영 남았다. 화면은 "쓰는 중"에서
멈추고 재시도도 막혔다.
**교훈**: 배포 전 `/admin/busy`로 진행 중 작업을 확인한다. 죽은 잡은 시간 기준으로
자동 해제한다. 사용자가 작업 중이라고 말하면 배포를 멈춘다(2026-08-01 같은 실수 2회 반복).

### 2026-07-31 · 타임아웃 고정값이 재작성을 죽임
90초 고정 타임아웃에 6000토큰 재작성이 걸려 개선 라운드째 사망.
**교훈**: 타임아웃은 출력 예산에 비례시킨다. → `app/llm.py`

### 2026-08-01 · 빈 응답을 예산 부족으로 오해 — 재시도 폭풍
thinking이 출력 예산을 다 먹으면 텍스트 0바이트 + stop_reason=max_tokens가 온다.
코드는 예산을 2배씩 늘려 재호출했고(콜당 최대 410초 × 3회), 결과는 여전히 빈 문자열.
호출부는 이를 '안전게이트 위반'으로 오해해 보정을 포기 → 77점 고착, polish 15분 정지.
**교훈**: 빈 응답은 예산이 아니라 thinking 문제다. 그리고 **빈 값을 조용히 반환하지
않는다** — 예외로 올려 호출부가 진짜 사유를 기록하게 한다.

### 2026-08-01 · 순서가 만든 유령 — 품질 루프가 채널 상태를 인질로 잡음
score_gate가 15분 붙들리자 그 뒤의 `_set_channel_status`가 실행되지 않아
channel_status={}가 됐고, 영상 버튼이 통째로 사라졌다.
**교훈**: 결정 가능한 값은 오래 걸리는 작업 앞에서 확정한다. 화면을 여는 데 필요한
상태를 품질 보정 뒤에 두지 않는다.

### 2026-08-01 · 삭제한 글이 되살아남
`save_piece`가 INSERT OR REPLACE라, 삭제 6분 뒤 끝난 다시쓰기 스레드가 지운 글을
다시 만들었다.
**교훈**: 삭제에는 묘비를 남기고 저장이 그것을 본다. 그리고 **묘비는 실제로 지웠을
때만** 남긴다 — 소유 검증 없이 남기면 남의 세트를 영구 동결시키는 취약점이 된다.

### 2026-08-01 · 요청하지 않은 산출물
`want`(사용자가 고른 플랫폼)가 상태 이름표에만 쓰이고 렌더 단계엔 전달되지 않아,
네이버만 눌러도 쇼츠·릴스가 만들어졌다. 워치독 자동 재시도도 요청 이력을 무시했다.
**교훈**: 사용자가 고른 것만 만든다. 자동 재시도는 요청 이력 안에서만.

## 측정 · 보고

### 2026-08-01 · 지면 판정 오탐 3종
인기글 링크가 리다이렉트라 blogId를 못 읽었고(지면 0으로 오판), 블록 제목과 결과
목록이 다른 컨테이너라 귀속이 빗나갔고, 플레이스에 딸린 업체 블로그 링크 1개를
'블로그 지면'으로 셌다.
**교훈**: 지면은 '블로그 글이 2개 이상 나열된 블록'만 인정한다.

### 2026-08-01 · 남의 가게를 우리 가게로 진단
상호만으로 지역검색을 해서 같은 이름의 다른 지역 업체를 우리 가게로 단정하고,
'업종을 고치라'는 틀린 처방을 냈다.
**교훈**: 지역 토큰이 전부 일치해야 우리 가게다. 일부만 맞으면 판정을 보류한다.

### 2026-08-02 · 측정 허위 — 만든 적 없는 지면에 "보이는 중"
대시보드가 "'부산 기장 중고차판매' 숏텐츠 NOW, 네이버 클립에 보이는 중"으로 표시했다.
원본을 뽑아보니 자사 블로그 ID 매칭은 참이었으나(첫 화면에 실제로 있음), '네이버 클립'
블록에 있던 것은 타사(no1motorss)였다. 우리 것이 아닌 블록명까지 섞어 표시한 것.
블록 귀속 자체가 'DOM 문서순서상 앞선 마지막 제목' 추정이라 정확도 미검증이었다.
**교훈**: 정직 게이트는 산출물만이 아니라 **측정에도** 적용된다. 검증 안 된 정밀함보다
두루뭉술한 사실이 낫다. → `tests/test_exposure_truth.py`로 박제

### 2026-08-02 · 키워드 하나만 보고 "미노출" 단정
추적 스크립트에 키워드를 하나만 넣어두고 "15시간째 미노출"이라고 보고했다. 실제로는
다른 두 검색어에서 이미 노출 중이었다.
**교훈**: 추적 키워드는 수동 등록하지 않는다(발행이 곧 편입). '미노출' 결론은 전 지면·
복수 키워드 확인 후에만.

## 보고 태도 (반복된 실수)

같은 실수를 여러 번 했다: **확인할 수 있는데 확인하지 않고 말했다.**
- 쇼츠 대본 메타데이터를 읽고 "네이버 영상 자막이 좋아졌다"고 보고 — 실제 영상에는
  고치기 전 자막이 그대로 구워져 있었다.
- 6개만 측정한 상태에서 "통합검색 노출은 1개뿐"이라고 단정 — 27개를 훑으니 9개였다.
- API가 값을 주지 않는 폐기 필드(플레이스 전화번호)를 보고 "비어 있으니 등록하라"고 처방.

**규칙**: 보고할 때 무엇을 근거로 그렇게 말하는지 함께 적는다. 확인 못 한 것은 못 했다고
말한다. 추측을 결과처럼 말하지 않는다.
